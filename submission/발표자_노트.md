## 1번 슬라이드

안녕하세요. 2조 송기훈, 최원제입니다. 웹캠 영상에서 양손의 손모양과 움직임을 인식해 원소 공격과 방어를 수행하는 ELEMENTAL BENDER를 제안합니다. 이번 발표는 조사와 계획 발표이며, 현재 구현과 이후 구현할 부분을 구분해서 설명하겠습니다.



## 2번 슬라이드

게임 그래픽 자체보다 카메라 영상에서 사용자의 의도를 판별하는 것이 컴퓨터비전의 핵심입니다. 같은 주먹이라도 이동 방향이 다르면 서로 다른 명령이고, 앞으로는 공격과 방어도 구분해야 합니다. 최종 동작은 사용자가 정의하며 아직 확정 전입니다.



## 3번 슬라이드

왼쪽은 실제로 모델과 Idle을 연결했던 프로토타입 화면입니다. 지금은 손 입력 전달과 임시 피해 효과를 확인하는 단계입니다. 적이 원소 공격을 예고하고 플레이어가 상성 방어로 대응하는 전투는 앞으로 추가할 계획입니다. 화면 예시를 완성된 상성 전투의 결과로 보시면 안 됩니다.



## 4번 슬라이드

웹캠은 Python이 한 번만 엽니다. 손동작 결과는 JSON으로 직렬화해 UDP로 전달하고, 웹캠 화면은 최신 JPEG를 HTTP로 제공해 Unity에서 표시합니다. 미리보기를 꺼도 인식은 계속됩니다. 현재 패킷에는 원소만 있고 공격과 방어 필드는 향후 추가해야 합니다.

- https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/python

## 5번 슬라이드

MediaPipe Hands의 기본 아이디어는 손바닥 검출과 랜드마크 추정을 결합하는 것입니다. 논문은 파이프라인 이해의 근거로 사용하며 현재 배포 모델의 세부 구조와 완전히 같다고 단정하지 않습니다. 현재 모델을 재학습한 것은 아닙니다. 학습된 모델은 관절 추정을 담당하고 원소 분류는 규칙 기반입니다.

- https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/python
- https://arxiv.org/abs/2006.10214

## 6번 슬라이드

HaGRID는 버전마다 규모가 다르므로 여기서는 현재 공식 저장소의 v2를 기준으로 표기했습니다. 정적 손모양과 동적 영상의 특성이 다르며, 어떤 데이터에도 우리 게임의 8개 공격/방어 라벨이 그대로 제공되지는 않습니다. EgoGesture는 촬영 시점이 달라 주 데이터로 선택하지 않습니다.

- https://github.com/hukenovs/hagrid
- https://www.qualcomm.com/developer/software/jester-dataset

## 7번 슬라이드

최종 동작을 먼저 확정한 뒤 수집합니다. 세 조건은 밝은 기준 거리, 밝은 먼 거리, 어두운 기준 거리입니다. 같은 사람의 영상 프레임을 섞어 학습과 테스트로 나누지 않습니다. 원본 영상을 기본 저장하지 않고 랜드마크 중심으로 기록하며, 전체 지연 측정용 영상은 별도 동의 후 수집합니다. 최종 테스트 참가자가 2명뿐이라는 한계도 보고합니다.



## 8번 슬라이드

손모양은 손목 기준 좌표로 비교할 수 있지만 각 손을 독립적으로 정규화하면 양손 간 거리가 사라질 수 있습니다. 그래서 개별 손 특징과 양손의 상대 이동을 함께 보관하려 합니다. 누락 프레임을 삭제하면 성공한 구간만 남아 평가가 낙관적으로 바뀌므로 마스크로 기록합니다.



## 9번 슬라이드

공식 노트북은 이미지 기반 Hand Landmarker 사용법의 근거이며 실시간 VIDEO 처리와 양손 규칙은 프로젝트에서 구현했습니다. kinivi 노트북의 정적 모델은 21개 좌표의 x/y 42차원을 입력받고 Dropout과 Dense 20, Dense 10을 거쳐 Softmax로 분류합니다. 동적 노트북의 기본값은 MLP이고 LSTM은 선택 경로입니다. 해당 예제는 이전 mp.solutions API를 사용하므로 Tasks API 호환 작업이 필요합니다. 이 분류기를 현재 코드에 통합하거나 학습한 것은 아닙니다.

- https://github.com/google-ai-edge/mediapipe-samples/blob/main/examples/hand_landmarker/python/hand_landmarker.ipynb
- https://github.com/kinivi/hand-gesture-recognition-mediapipe

## 10번 슬라이드

V는 최종 8동작을 정하기 전의 예비 입력입니다. 현재는 공격/방어를 구별하지 않고 WATER라는 원소 결과를 보냅니다. Python은 제스처 지속 시간과 재무장을 검사하고 Unity는 중복 패킷과 게임 쿨다운을 검사합니다. 애니메이션과 상성 방어는 앞으로 원소와 action 필드를 나누어 연결할 예정입니다.

- https://github.com/MonoTrace/elemental-bender

## 13번 슬라이드
